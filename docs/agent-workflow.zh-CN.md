# Agent 工作流

本文说明 AI Agent 与 ReVitAI Bridge 之间建议采用的调用契约。

## 角色

- **Agent**：理解用户目标、选择工具、根据回读结果继续判断。
- **MCP Server**：把实时 Revit 工具目录转换成 MCP 工具。
- **Bridge**：校验请求，把工作调度到 Revit 主线程，返回结构化结果。
- **Tool Dispatcher**：负责 schema、单位、事务、回滚和回读。
- **用户**：决定是否保存、同步、关闭文档，以及是否执行破坏性操作。

## 核心循环

```text
用户目标
   |
   v
读取上下文 -> 选择工具 -> 预检 -> 查询或执行修改
   |                                  |
   |                                  v
   +------------------------------ 回读结果
   |
   v
报告观测值、未确认项和下一步安全动作
```

## 必需步骤

### 1. 读取上下文

优先调用：

- `ping`
- `get_document_info` 或 `get_document_snapshot`
- `get_active_view`
- `get_project_units`

不能沿用上一次会话的文档、视图、标高、轴网或族类型假设。

### 2. 使用实时工具目录

调用 `tools.list` 或 MCP `tools/list`，只能使用目录中实际存在的工具名。不要发明工具名，也不要在类型化工具可用时静默退化为任意代码执行。

### 3. 预检对象 ID

写操作前必须从当前文档解析真实 ID：

- 标高层次：`get_all_levels`
- 轴网：`get_all_grids`
- 族类型：`get_family_types`
- 墙和楼板类型：`get_wall_types`、`get_floor_types`
- 房间边界：`get_room_boundaries`
- 元素：`element_query` 或 `get_element_geometry`

如果所需对象不存在，应明确报告缺失项，不能伪造 ID。

### 4. 先计划再写入

支持时先执行 `dryRun: true`。多步骤任务使用 `apply_drawing_plan` 或 `batch`，并显式声明依赖。

推荐阶段：

1. 标高和基准；
2. 轴网；
3. 墙体和楼板；
4. 门窗等宿主元素；
5. 注释和尺寸；
6. 裁剪视图并导出。

### 5. 一次执行一个逻辑修改

每个写操作应有明确目的和独立事务。失败必须回滚。不要把一个含糊请求扩展成整个文档的大范围修改。

### 6. 必须回读

写操作完成后重新查询受影响元素，并报告：

- 请求值；
- 实际观测值；
- 返回的元素 ID；
- 警告信息；
- 无法确认的内容。

### 7. 停在用户边界

除非用户明确要求，否则不得保存、同步、关闭或覆盖文档。不得把 dry-run 自动升级为正式写入。

## 工程图生成流程

建议顺序：

1. 如有需要，先导入 PDF 底图。
2. 读取当前视图和文档上下文。
3. 创建或更新标高、轴网。
4. 创建楼板、墙体、房间、柱和梁。
5. 添加门窗、详图线、文字和尺寸。
6. 调整视图裁剪并导出图片。
7. 回读创建结果并给出简明摘要。

## 失败处理

- `revit_context_not_ready`：打开 Revit 宿主后重试。
- `tool_not_found`：刷新实时目录，不要自行替换工具。
- `astools_tool_error`：阅读结构化错误并修正参数。
- 事务失败：不得声称成功，应报告已回滚。
- 单位不明确：先读取 schema 和项目单位。
- 缺少族或类型：解析真实已加载类型，或停止并报告。

## 反模式

- 使用过期工具目录调用。
- 硬编码来自其他文档的 ElementId。
- 把 dry-run 当成已完成写入。
- 用薄墙或细管伪造轴网。
- 已有类型化工具时仍调用任意代码。
- 没有独立回读就宣称成功。
